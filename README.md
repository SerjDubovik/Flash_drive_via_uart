# Flash_drive_via_uart

# Файловый браузер SD-карты для STM32F407

Прошивка находится в папке `STM32F407_cubeFATfs_JSON`, приложение Windows Forms на C# — в `SdCardBrowser`. Приложение показывает содержимое SD-карты на плате, открывает папки двойным щелчком, создаёт пустые файлы и папки, переименовывает, перемещает и удаляет их. После изменения текущая папка перечитывается с платы. Кнопка «Обновить» позволяет перечитать её вручную.

Перемещение выполняется внутри SD-карты. В диалоге «Переместить» укажите путь существующей папки, например `/Архив`. Удаление требует подтверждения и применяется к файлам и пустым папкам. «Загрузить на карту…» записывает выбранные на ПК файлы в текущую папку карты. «Скачать на ПК…» сохраняет выделенный файл по выбранному пути. Передача показывает прогресс и поддерживает отмену. Двойной щелчок по файлу открывает встроенный редактор или просмотрщик.

- Редактор поддерживает TXT, CSV, LOG, JSON, XML, INI, MD, CFG, CONF, YAML и YML до 1 МиБ. Он сохраняет исходную кодировку UTF-8 или Unicode с BOM. Для текста без BOM, который не декодируется как UTF-8, используется Windows‑1251. Кнопка «Сохранить на карту» и Ctrl+S записывают правки обратно в тот же файл.
- Просмотрщик поддерживает PNG, JPEG, BMP, GIF и TIFF до 16 МиБ и 32 мегапикселей. Файлы других форматов и крупные файлы можно скачать на ПК.
- При замене прошивка сначала принимает и закрывает временный файл, затем сохраняет прежний файл под резервным именем и публикует новый. Если питание пропадёт на этапе переименования, в корне карты могут остаться файлы `/~UXXXXXXXX.TMP` и `/~BXXXXXXXX.BAK`. Резервный файл содержит прежнюю версию.
- Размер файла для передачи ограничен форматом FAT32. При 115200 бод и кодировании в hex скорость составляет до примерно 5,5 КиБ/с, поэтому крупные файлы передаются долго.

## Подключение

1. Установите в картридер карту с FAT или FAT32 и прошейте обновлённый ELF или HEX. В VS Code используйте профиль «DAP link Debug» или задачу `flash` для DAPLink. Прошивка монтирует существующую файловую систему. Карты exFAT не поддерживаются.
2. Подключите адаптер USB–UART с логическими уровнями 3,3 В. Соедините TX адаптера с PA10 (USART1_RX), RX адаптера с PA9 (USART1_TX) и GND с GND платы. Параметры порта — **115200, 8N1, без управления потоком**.
3. Запустите приложение, выберите COM-порт адаптера и нажмите «Подключиться». Если порт открыт в терминале, закройте его перед подключением.

## Сборка

Для приложения нужен .NET 10 SDK с поддержкой Windows Desktop. Из рабочей папки выполните:

```powershell
dotnet build .\SdCardBrowser\SdCardBrowser.csproj -c Release
dotnet run --project .\SdCardBrowser\SdCardBrowser.csproj -c Release --no-build
```

Для прошивки используйте CMake, Ninja и ARM GCC из настроек проекта. В PowerShell с установленным комплектом `C:VStools`:

```powershell
cd .\STM32F407_cubeFATfs_JSON
$env:Path = 'C:\VStools\gnu-tools-for-stm32\tools\bin;' + $env:Path
cmake --preset debug -DCMAKE_MAKE_PROGRAM=C:/VStools/ninja/ninja.exe
cmake --build --preset debug
```

Цель CMake сохраняет исходное имя `STM32F407_cubeLed`. Готовые ELF и HEX появляются в `STM32F407_cubeFATfs_JSON/build/debug`.

## Как обновлять конфигурацию в STM32CubeMX

1. Перед генерацией сохраните изменения в Git или сделайте копию папки прошивки. Откройте копию `STM32F407VGT6.ioc` в отдельной папке и сгенерируйте проект туда. В CubeMX оставьте включённым **Project Manager → Code Generator → Keep User Code when re-generating**. Этот параметр сохраняет код между маркерами `USER CODE BEGIN/END` в генерируемых файлах.
2. Сравните результат с рабочим проектом и перенесите изменения для нужной периферии. Для SPI1 это `MX_SPI1_Init` и его вызов в `main.c`, GPIO и тактирование в `stm32f4xx_hal_msp.c`, `HAL_SPI_MODULE_ENABLED` и соответствующие файлы HAL. Сохраните обновлённый `STM32F407VGT6.ioc` в рабочей папке. Рабочая сборка использует верхний `CMakeLists.txt` и свои настройки VS Code. Новый `cmake/stm32cubemx/CMakeLists.txt` служит списком файлов для отдельной сборки, сгенерированной CubeMX.
3. Проверьте FatFs. Браузеру нужны `_USE_LFN=2`, `_LFN_UNICODE=1` и `ccsbcs.c`. В рабочей папке сохраните правки `sd_diskio.c` с тайм-аутами и `diskio.c` с повторной инициализацией карты. Эти два файла CubeMX может перезаписать при генерации поверх проекта.
4. В VS Code выберите пресет **debug** и выполните **CMake: Build**. Если проект перенесли или CMake использует старые пути, выполните **CMake: Delete Cache and Reconfigure** и повторите сборку. Для записи на плату используйте задачу **flash** или профиль **DAP link Debug**.

## Проверка SPI-флеш W25Q16

Прошейте сборку `debug` и освободите COM-порт, если его занял SdCardBrowser. SPI1 работает в режиме 0 с делителем 32, примерно 2,625 МГц. Подключения для текущего `.ioc` — PB3 → CLK, PB4 ← DO/IO1, PB5 → DI/IO0, PA15 → /CS и общий GND. Проверьте напряжение питания и логические уровни по полному обозначению микросхемы. Например, W25Q16JV и W25Q16JW рассчитаны на разные напряжения. [Документация Winbond](https://www.winbond.com/hq/product/code-storage-flash/qspi-nor/w25q-jv/?__locale=en&partNo=W25Q16JVSNAM)

В PowerShell подставьте номер своего COM-порта и выполните:

```powershell
$port = [System.IO.Ports.SerialPort]::new('COM5', 115200)
$port.ReadTimeout = 3000
try {
    $port.Open()
    $port.DiscardInBuffer()
    $port.WriteLine(([string][char]0x1E) + '{"id":1,"op":"flashid"}')
    do {
        $reply = $port.ReadLine() | ConvertFrom-Json
        $reply | ConvertTo-Json -Compress
    } until ($reply.PSObject.Properties['result'])
} finally {
    $port.Dispose()
}
```

Пример ответа для W25Q16JV с пустым началом памяти:

```json
{"id":1,"jedec":"EF4015","detected":true,"sr1":0,"sr2":2,"data":"FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF","spi":0}
{"id":1,"result":0}
```

`flashid` читает JEDEC ID, два регистра состояния и 16 байт с адреса `0x000000`, если микросхема готова. `detected:true` означает, что ID совпал с поддерживаемым вариантом, а `result:0` подтверждает выполнение запроса. Значения `sr1`, `sr2` и `data` зависят от микросхемы и её содержимого. При установленном бите BUSY в `sr1` поле `data` пустое. Если сам ID равен `FFFFFF` или `000000`, проверьте питание, `/CS` и линию MISO.

## Файлы на W25Q16

Прошейте обновлённый STM32 и запустите новую версию SdCardBrowser. Рядом с подключением выберите **SD-карта** или **W25Q16**. Накопитель можно переключать во время подключения, когда передача завершена. На выбранном томе доступны папки, создание и удаление файлов, загрузка и скачивание, перетаскивание между ПК и платой, а также редактор `.json`.

При первом подключении к W25Q16 без FAT приложение предложит создать файловую систему. Подтвердите инициализацию, если содержимое чипа можно заменить. Действие относится к W25Q16. Уже смонтированный том сохраняется при повторном подключении.

Для будущего чтения конфигурации в прошивке используйте явный путь FatFs, например `1:/config.json`. SD-карта доступна как `0:/`, W25Q16 как `1:/`. W25Q16 имеет 2 МиБ сырой памяти. Часть пространства занимает FAT12. Сектор FatFs равен сектору стирания NOR в 4 КиБ. Драйвер пропускает неизменившиеся сектора и проверяет записанные данные повторным чтением. Распределение износа не реализовано. Такой том подходит для периодического сохранения конфигурации. [FatFs](https://elm-chan.org/fsw/ff/doc/dioctl.html) · [Даташит W25Q16JV](https://mm.digikey.com/Volume0/opasdata/d220001/medias/docus/6661/W25Q16JV.pdf)

## Настройка скорости USART1

Создайте на W25Q16 папку `sys` и файл `settings_uart.json`. Запишите один числовой параметр, например:

```json
{"baudRate": 230400}
```

Поддерживаемые скорости — 9600, 19200, 38400, 57600, 115200, 230400 и 460800 бод. Сохраните файл в UTF-8, перезапустите плату и выберите ту же скорость рядом с COM-портом в SdCardBrowser. При недоступном файле, ошибке чтения, неверном формате или неподдерживаемом значении используется 115200 бод. Скорость применяется в блоке `USART1_MspInit 0` перед настройкой регистров USART1. Для повторной генерации сохраняйте порядок инициализации FATFS и SPI1 перед USART1.

Внизу окна SdCardBrowser отображаются свободные байты выбранного тома. Значение обновляется при чтении списка каталога. Первая проверка на большой SD-карте может занять время, если FatFs нужно просканировать таблицу размещения. **Файл → Выход** закрывает COM-порт после завершения текущей команды или отмены передачи.

## Протокол UART

Каждый запрос состоит из байта `0x1E`, одного JSON-объекта и байта LF (`0x0A`). JSON передаётся в ASCII. Для остальных символов используются JSON-последовательности `\uXXXX`. Новый `0x1E` сбрасывает незавершённый запрос. Клиент отправляет следующую команду после итогового ответа на предыдущую. По тайм-ауту изменяющая команда автоматически не повторяется.

| Операция | Поля кроме числового `id` | Действие |
| --- | --- | --- |
| `mount` | `op` | Смонтировать и выбрать SD-карту |
| `mntnor` | `op` | Смонтировать и выбрать W25Q16 |
| `norinit` | `op` | Создать FAT на W25Q16, если том отсутствует |
| `list` | `op`, `path` | Прочитать каталог |
| `space` | `op` | Вернуть свободное место выбранного тома в поле `freeBytes` |
| `create` | `op`, `path` | Создать пустой файл |
| `mkdir` | `op`, `path` | Создать папку |
| `move` | `op`, `path`, `to` | Переместить или переименовать объект |
| `delete` | `op`, `path` | Удалить файл или пустую папку |
| `get` | `op`, `path` | Открыть файл для чтения, вернуть `size` |
| `read` | `op`, `offset` | Вернуть следующий блок с полями `offset`, `data`, `crc` |
| `put` / `replace` | `op`, `path`, `size` | Начать запись нового файла или замену существующего |
| `write` | `op`, `offset`, `data`, `crc` | Принять следующий блок |
| `finish` / `abort` | `op` | Завершить или прервать передачу |

После успешного `mount` или `mntnor` файловые команды с путём `/…` работают на выбранном томе. Версия протокола этой прошивки — `3`. Прошивки с поддержкой передачи добавляют поле `version` со значением `2` или выше в ответ на монтирование. Поле `data` содержит до 2048 байт в hex. `size`, `offset` и `crc` передаются числами. `crc` — CRC-32/ISO-HDLC по исходным байтам блока. Смещения начинаются с нуля и идут подряд. На `get` и `read` плата отправляет строку данных, а затем строку с итоговым `result`. После 30 секунд без блоков активная передача прерывается.

Пути абсолютные, с разделителем `/`. Максимальная длина пути — 512 кодовых единиц UTF-16, отдельного имени — 255. Новые имена могут содержать пробелы внутри и кириллицу. При совпадении имён существующий объект сохраняется. Команды для корня ограничены чтением каталога.

Пример полезной нагрузки запроса:

```json
{"id":42,"op":"list","path":"/"}
```

Пример ответа. Каждая строка заканчивается LF. Поле `result` содержит итоговый код `FRESULT` (`0` означает успех). Кадры с `id:0` сообщают об ошибке, для которой плата не смогла определить номер запроса.

```json
{"id":42,"name":"REPORT.TXT","directory":false,"size":128}
{"id":42,"result":0}
```

Модуль кодовых страниц `ccsbcs.c` взят из официального архива FatFs R0.12c. 
[FatFs](https://elm-chan.org/fsw/ff/)
