# Flash_drive_via_uart

# Файловый браузер SD-карты для STM32F407

Прошивка находится в папке `STM32F407_cubeFATfs_JSON`, приложение Windows Forms на C# — в `SdCardBrowser`. Приложение показывает содержимое SD-карты на плате, открывает папки двойным щелчком, создаёт пустые файлы и папки, переименовывает, перемещает и удаляет их. После изменения текущая папка перечитывается с платы. Кнопка «Обновить» позволяет перечитать её вручную.

Перемещение выполняется внутри SD-карты. В диалоге «Переместить» укажите путь существующей папки, например `/Архив`. Удаление требует подтверждения и применяется к файлам и пустым папкам. «Загрузить на карту…» записывает выбранные на ПК файлы в текущую папку карты. «Скачать на ПК…» сохраняет выделенный файл по выбранному пути. Передача показывает прогресс и поддерживает отмену. Двойной щелчок по файлу открывает встроенный редактор или просмотрщик.

- Редактор поддерживает TXT, CSV, LOG, JSON, XML, INI, MD, CFG, CONF, YAML и YML до 1 МиБ. Он сохраняет исходную кодировку UTF-8 или Unicode с BOM. Для текста без BOM, который не декодируется как UTF-8, используется Windows‑1251. Кнопка «Сохранить на карту» и Ctrl+S записывают правки обратно в тот же файл.
- Просмотрщик поддерживает PNG, JPEG, BMP, GIF и TIFF до 16 МиБ и 32 мегапикселей. Файлы других форматов и крупные файлы можно скачать на ПК.
- При замене прошивка сначала принимает и закрывает временный файл, затем сохраняет прежний файл под резервным именем и публикует новый. Если питание пропадёт на этапе переименования, в корне карты могут остаться файлы `/~UXXXXXXXX.TMP` и `/~BXXXXXXXX.BAK`. Резервный файл содержит прежнюю версию.
- Размер файла для передачи ограничен форматом FAT32. При 115200 бод и кодировании в hex скорость составляет до примерно 5,5 КиБ/с, поэтому крупные файлы передаются долго.

## Подключение

1. Установите в картридер карту с FAT или FAT32 и прошейте обновлённый ELF или HEX. В VS Code используйте профиль «DAP link Debug» или задачу `flash` для DAPLink. Прошивка монтирует существующую файловую систему. Карты exFAT не поддерживаются.
2. Подключите адаптер USB–UART с логическими уровнями 3,3 В. Соедините TX адаптера с PA10 (USART1_RX), RX адаптера с PA9 (USART1_TX) и GND с GND платы. Параметры порта — **115200, 8N1, без управления потоком**.
3. Запустите приложение, выберите COM-порт адаптера и нажмите «Подключиться». Если порт открыт в терминале, закройте его перед подключением.

## Сборка

Для приложения нужен .NET 10 SDK с поддержкой Windows Desktop. Из рабочей папки выполните:

```powershell
dotnet build .\SdCardBrowser\SdCardBrowser.csproj -c Release
dotnet run --project .\SdCardBrowser\SdCardBrowser.csproj -c Release --no-build
```

Для прошивки используйте CMake, Ninja и ARM GCC из настроек проекта. В PowerShell с установленным комплектом `C:VStools`:

```powershell
cd .\STM32F407_cubeFATfs_JSON
$env:Path = 'C:\VStools\gnu-tools-for-stm32\tools\bin;' + $env:Path
cmake --preset debug -DCMAKE_MAKE_PROGRAM=C:/VStools/ninja/ninja.exe
cmake --build --preset debug
```

Цель CMake сохраняет исходное имя `STM32F407_cubeLed`. Готовые ELF и HEX появляются в `STM32F407_cubeFATfs_JSON/build/debug`.

## Протокол UART

Каждый запрос состоит из байта `0x1E`, одного JSON-объекта и байта LF (`0x0A`). JSON передаётся в ASCII. Для остальных символов используются JSON-последовательности `\uXXXX`. Новый `0x1E` сбрасывает незавершённый запрос. Клиент отправляет следующую команду после итогового ответа на предыдущую. По тайм-ауту изменяющая команда автоматически не повторяется.

| Операция | Поля кроме числового `id` | Действие |
| --- | --- | --- |
| `mount` | `op` | Смонтировать карту |
| `list` | `op`, `path` | Прочитать каталог |
| `create` | `op`, `path` | Создать пустой файл |
| `mkdir` | `op`, `path` | Создать папку |
| `move` | `op`, `path`, `to` | Переместить или переименовать объект |
| `delete` | `op`, `path` | Удалить файл или пустую папку |
| `get` | `op`, `path` | Открыть файл для чтения, вернуть `size` |
| `read` | `op`, `offset` | Вернуть следующий блок с полями `offset`, `data`, `crc` |
| `put` / `replace` | `op`, `path`, `size` | Начать запись нового файла или замену существующего |
| `write` | `op`, `offset`, `data`, `crc` | Принять следующий блок |
| `finish` / `abort` | `op` | Завершить или прервать передачу |

Прошивка с поддержкой передач добавляет `"version":2` в ответ на `mount`. Поле `data` содержит до 2048 байт в hex. `size`, `offset` и `crc` передаются числами. `crc` — CRC-32/ISO-HDLC по исходным байтам блока. Смещения начинаются с нуля и идут подряд. На `get` и `read` плата отправляет строку данных, а затем строку с итоговым `result`. После 30 секунд без блоков активная передача прерывается.

Пути абсолютные, с разделителем `/`. Максимальная длина пути — 512 кодовых единиц UTF-16, отдельного имени — 255. Новые имена могут содержать пробелы внутри и кириллицу. При совпадении имён существующий объект сохраняется. Команды для корня ограничены чтением каталога.

Пример полезной нагрузки запроса:

```json
{"id":42,"op":"list","path":"/"}
```

Пример ответа. Каждая строка заканчивается LF. Поле `result` содержит итоговый код `FRESULT` (`0` означает успех). Кадры с `id:0` сообщают об ошибке, для которой плата не смогла определить номер запроса.

```json
{"id":42,"name":"REPORT.TXT","directory":false,"size":128}
{"id":42,"result":0}
```

Модуль кодовых страниц `ccsbcs.c` взят из официального архива FatFs R0.12c.
